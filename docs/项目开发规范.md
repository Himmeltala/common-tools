# 常用工具箱项目开发规范

> 本文档是「常用工具箱」项目的唯一权威开发规范，所有后续开发必须遵守。
> 文档描述项目架构、设计思路，并给出 CSS、布局、样式、API、状态管理等各类约定。

---

## 1. 项目概述

「常用工具箱」是一个基于 **Electron + Vue 3 + Vite + TypeScript** 的 Windows 桌面工具箱，集成 Markdown 预览与 PDF 转换、数据库 DDL 转换、Excel 处理等常用工具，支持按类别扩展。

核心特征：

- 双进程架构（Electron 主进程 + Vue 渲染进程）
- 注册表 + 执行器双模式，新增工具只需注册，无需修改框架代码
- JSON Schema 驱动的动态设置系统
- 安全 IPC 桥接（contextBridge + 通道白名单）
- 原生 Windows 通知 + 应用内日志面板

## 3. 项目架构

### 3.1 进程模型

项目采用 Electron 标准双进程模型，主进程与渲染进程通过 `contextBridge` 暴露的 `window.electronAPI` 通信：

```
+---------------------------+          +------------------------------+
|        渲染进程 (src/)      |          |        主进程 (electron/)      |
|                           |  invoke  |                              |
|  Vue 3 组件               | -------> |  ipcMain.handle() 处理器      |
|  toolRegistry 注册表       |   IPC    |  Services（业务服务）          |
|  Element Plus UI          | <------- |  toolExecutors 注册表          |
|  Pinia / Vue Router       |  事件回推  |                              |
+---------------------------+          +------------------------------+
        |                                       |
        +-------- preload.ts（白名单桥接） --------+
```

- **主进程**：负责窗口生命周期、菜单、IPC handler、文件读写、原生通知、Python 子进程、PDF 生成等系统级能力。
- **preload**：唯一的通信桥接层，只暴露 `invoke` / `on` 两个方法，并对 channel 做白名单校验。
- **渲染进程**：纯 UI 与业务展示，不直接接触 Node / 文件系统能力，所有系统能力通过 IPC 调用。

安全配置（`electron/main.ts` 创建窗口时）：

```ts
webPreferences: {
  preload: join(__dirname, 'preload.js'),
  contextIsolation: true,   // 上下文隔离，必须保持
  nodeIntegration: false,   // 渲染进程禁用 Node，必须保持
},
```

## 4. 项目设计思路

### 4.1 注册表模式（工具扩展）

前端采用「工具类别注册表」实现工具的可插拔扩展。所有工具类别通过 `toolRegistry.register()` 注册，侧边栏菜单、首页卡片、路由分发全部由注册表驱动，**新增工具无需修改框架代码**。

```ts
// src/types/tool.ts
export interface ToolCategory {
  id: string // 类别唯一标识，如 'markdown'
  label: string // 显示名称
  icon: string // Element Plus 图标组件名
  tools: Tool[] // 类别下的工具列表
}

export interface Tool {
  id: string
  label: string
  description: string
  icon: string
  component: Component
  executors?: string[] // 依赖的主进程执行器 id（纯前端工具留空）
}
```

### 4.2 执行器模式（主进程能力接入）

主进程采用「工具执行器」抽象。渲染进程只调用 `tool:execute`，具体逻辑由注册的执行器实现，执行器按业务领域分散到 `electron/services/<category>/index.ts`。

```ts
// electron/services/tool-executor.service.ts
export interface ToolExecutor {
  id: string
  execute(params: Record<string, unknown>, ctx: ToolExecutorContext): Promise<ToolExecuteResult>
}
```

`ToolExecutorContext` 向执行器注入受限的主进程能力（目前仅 `app.getPath`），**禁止**在 ctx 中暴露超出必要的能力。

### 4.3 Schema 驱动设置

设置界面完全由 `assets/settings_schema.json` 描述（分类 -> 分组 -> 设置项），`SettingsModal.vue` 按 Schema 动态渲染表单，`AppSettings` 按 Schema 生成默认值。新增设置只需改 Schema，无需改 UI 代码。

设置项支持类型：`checkbox`（el-switch）、`combo`（el-select）、`spinbox`（el-input-number）、`text`（el-input），并支持 `depends_on` / `depends_value` 实现条件显隐。

### 4.4 安全 IPC 桥接

- 渲染进程只能通过 `window.electronAPI.invoke()` / `window.electronAPI.on()` 通信。
- `preload.ts` 对 channel 做**白名单前缀校验**，非白名单通道直接抛错拒绝。
- 新增 IPC 通道必须在 `ALLOWED_PREFIXES` 中登记（见 8.1）。

### 4.5 数据持久化

- **设置**：点号嵌套 Key -> 用户数据目录 `assets/settings.json`。
- **通用存储**：每个 key 独立存储为 `store/{key}.json`，key 校验防路径穿越。
- **通知**：用户数据目录 `assets/notifications.json`。
- **模板同步**：首次启动/版本升级时，将源码 `assets/` 同步到用户数据目录，`settings_schema.json` 每次强制同步。

### 4.6 设计原则总结

1. **可扩展优先**：注册表 + 执行器，新增功能 = 新增文件 + 注册。
2. **安全默认**：contextIsolation、白名单、最小能力暴露。
3. **配置外置**：Schema 驱动设置，界面与配置解耦。
4. **职责分离**：UI（渲染进程）与系统能力（主进程）严格分离。
5. **一致体验**：统一布局组件、统一日志、统一通知、统一主题。
6. **规范落地**：用自定义 ESLint 规则把约定固化为可执行的检查。

## 5. 开发规范

### 5.1 通用编码规范

#### 语言与格式

- 全项目使用 **TypeScript**，开启 `strict`。
- 代码格式化统一交给 **Prettier**，配置见 `.prettierrc`（无分号、单引号、trailingComma: all、printWidth 120、tabWidth 2、LF）。
- 提交前执行 `pnpm run format` 与 `pnpm run lint`。

#### 路径别名（强制）

**禁止相对路径导入**（`./` 和 `../`），统一使用别名（由 ESLint 规则 `local/no-relative-imports` 强制）：

```ts
// 正确
import ToolLayout from '@/components/ToolLayout.vue'
import { toolExecutors } from '@electron/services/tool-executor.service'
// 错误
import ToolLayout from '../components/ToolLayout.vue'
```

#### 文件头注释（强制）

每个 `.vue` / `.ts` / `.js` 源文件必须以文件头注释开头，且必须包含 `Author`、`Date`、`LastEditors`、`LastEditTime`、`FilePath`、`Description` 六个字段（由 `local/illegal-header-annotation` 强制）：

- `.vue` 使用 HTML 注释 `<!-- ... -->`
- `.ts` / `.js` 使用 `/* ... */`

```ts
/*
 * @Author: zhengrenfu
 * @Date: 2026-08-14
 * @LastEditors: zhengrenfu
 * @LastEditTime: 2026-08-14
 * @FilePath: /src/utils/foo.ts
 * @Description: Foo 工具函数
 */
```

#### 注释规范（强制）

- 单行注释 `//` 后必须跟一个空格。
- 块注释必须使用 JSDoc 格式 `/** */`，不得用作章节分隔线。
- 仅含描述、无标签（`@param`/`@returns` 等）的注释块改用 `//` 单行注释。
- 函数/方法使用 JSDoc 标注参数与返回值。
- **禁止** AI 风格表述（如「新增了…」「这个函数…」等）与特殊符号（箭头、线条、emoji）。

```ts
/**
 * 将文本截断到前 maxLines 行
 * @param text 原始文本
 * @param maxLines 最大显示行数
 * @returns 截断结果
 */
export function truncateLines(text: string, maxLines: number): TruncateLinesResult
```

#### 命名规范

| 类型         | 规范             | 示例                          |
| ------------ | ---------------- | ----------------------------- |
| 文件/目录    | kebab-case       | `tool-layout`, `log.store.ts` |
| Vue 组件     | PascalCase 多词  | `GlobalLogPanel.vue`          |
| 类型/接口    | PascalCase       | `ToolCategory`                |
| 变量/函数    | camelCase        | `handleFileOpen`              |
| 常量         | UPPER_SNAKE_CASE | `MAX_DISPLAY_LINES`           |
| Store 文件   | `*.store.ts`     | `log.store.ts`                |
| Service 文件 | `*.service.ts`   | `settings.service.ts`         |

### 5.2 目录与命名规范

#### `src/components/`（通用组件）

- 组件名必须 **PascalCase 多词**（由 `local/illegal-component-using` 强制）。
- 目录下包含多个 `.vue` 文件时，**不可使用 `index.vue` 作为入口**，应使用具名文件。

#### `src/modals/`（弹窗）

- 弹窗组件文件必须放在 `modals/` 目录，且**以 `Modal.vue` 结尾**。
- 弹窗 `<template>` 中必须包含 `<el-dialog>`。
- 业务组件使用弹窗时**必须搭配 `useModal`**（由 `local/illegal-modal-using` 强制）。

#### 图片资源

- **禁止**在 `src/` 目录下存放图片文件（由 `local/no-image-in-src`、`local/no-image-in-views` 强制）。
- 图片统一放 `public/static/image/`，模板中路径必须为 `/static/image/...`。

#### 未引用文件

- `local/no-unused-files`（warn）会提示未被引用的文件，确认无用后应删除。

### 5.3 Vue 组件规范

#### 必须使用 `<script setup lang="ts">`

所有 `.vue` 文件使用组合式 API 的 `script setup` 语法糖（由 `local/required-script-setup` 强制）：

```vue
<script setup lang="ts">
import { ref, computed } from 'vue'
// ...
</script>
```

#### 组件结构顺序

推荐按以下顺序组织：

```vue
<template>...</template>
<script setup lang="ts">
...
</script>
<style scoped>
...
</style>
```

#### 模板约定

- Element Plus 组件统一加 `size="small"` 以适配桌面紧凑布局。
- 图标使用 `@element-plus/icons-vue`，通过 `:icon="FolderOpened"` 绑定（`<script setup>` 中 import 图标后直接作为按钮 icon 传入）。
- 列表渲染使用 `:key` 绑定唯一标识。
- 涉及大文本渲染时使用 `truncateLines()` 限制行数（见 5.6 性能规范）。

#### 类型与 Props

- 使用 `defineProps` / `defineEmits`，优先类型化声明：

```ts
const props = defineProps<{ copyText?: string }>()
const emit = defineEmits<{ 'update:visible': [value: boolean] }>()
```

### 5.4 CSS / 样式规范

#### 设计变量优先（强制）

`<style>` 中**禁止硬编码颜色值**（hex / rgb / 命名色），必须使用 CSS 变量（由 `local/use-design-variables` 强制，`src/tools/` 目录下的工具组件豁免）。

**优先使用 Element Plus 语义变量**：

```css
/* 正确 */
color: var(--el-text-color-primary);
background: var(--el-bg-color);
border: 1px solid var(--el-border-color);
color: var(--el-color-danger);

/* 错误 */
color: #333;
background: #fff;
```

**常用 Element Plus 变量**：

| 变量                                                       | 用途                 |
| ---------------------------------------------------------- | -------------------- |
| `--el-bg-color` / `--el-bg-color-overlay`                  | 背景色               |
| `--el-text-color-primary` / `-secondary` / `-placeholder`  | 文本色               |
| `--el-border-color` / `-lighter`                           | 边框色               |
| `--el-color-primary` / `-success` / `-danger` / `-warning` | 语义色               |
| `--el-color-primary-light-5`                               | 主色浅色（hover 等） |
| `--el-fill-color-blank` / `-light`                         | 填充色               |
| `--el-font-size-base` / `-small` / `-extra-small`          | 字号                 |
| `--el-font-family` / `--el-font-weight-primary`            | 字体/字重            |

#### 项目级设计 Token

全局间距、布局尺寸统一使用 `App.vue` 中定义的 `--app-*` 变量（见 8.2），**不要魔法数字**：

```css
/* 正确 */
gap: var(--app-gap-toolbar);
padding: var(--app-space-2);

/* 错误 */
gap: 8px;
padding: 12px;
```

#### 作用域

- 组件样式使用 `scoped`，避免样式泄漏。
- 需要穿透到子组件（如 ToolLayout 的插槽内容、Element Plus 内部）时使用 `:deep()`：

```css
:deep(.editor-textarea .el-textarea__inner) {
  font-family: 'Consolas', 'Monaco', 'Courier New', monospace;
}
```

#### 主题适配

- 主题切换通过给 `<html>` 添加/移除 `.dark` class，并设置 `data-theme` 属性实现。
- 组件颜色全部引用 Element Plus 变量，自动适配明暗主题，**无需**在组件中写主题分支。

#### 字体约定

- 正文：`'Microsoft YaHei', Arial, sans-serif`（Element Plus 默认 `--el-font-family`）。
- 代码/等宽：`'Consolas', 'Monaco', 'Courier New', monospace`。

#### 全局 Reset

`App.vue` 已提供全局 reset（`* { margin:0; padding:0; box-sizing:border-box }`），组件内无需重复 reset。

### 5.5 布局规范

#### 整体布局

应用根布局为「左侧固定侧边栏 + 右侧内容区」：

```
+--------+--------------------------+
|        |      main-area (路由)     |
| sidebar|--------------------------|
| 220px  |  GlobalLogPanel (可折叠)  |
+--------+--------------------------+
```

- 侧边栏宽度由 `--app-sidebar-width` 控制（当前 220px）。
- 根布局使用 `display: flex`，`html/body/#app` 均 `height:100%` + `overflow:hidden`。

#### 工具页统一布局（ToolLayout.vue）

**所有工具页面必须复用 `ToolLayout` 组件**，通过具名插槽填充内容：

```vue
<ToolLayout :copy-text="outputText">
  <template #toolbar>       <!-- 顶部工具栏：打开/清空/参数/保存 -->
  <template #left-header>   <!-- 左栏标题 -->
  <template #left>          <!-- 左栏内容（输入） -->
  <template #right-header>  <!-- 右栏标题（自动带复制按钮） -->
  <template #right>         <!-- 右栏内容（输出） -->
</ToolLayout>
```

`ToolLayout` 提供的能力：

- 顶部工具栏 + 左右双栏结构，左右栏等比（`flex:1`）。
- 传入 `copy-text` 后，右栏标题自动显示「复制」按钮。
- 提供一组**通用深样式类**供插槽内容使用（见下方）。

#### 通用样式类（配合 ToolLayout 使用）

| 类名                | 用途                             |
| ------------------- | -------------------------------- |
| `.toolbar-label`    | 工具栏中的参数标签               |
| `.file-name`        | 当前打开文件名（单行省略）       |
| `.editor-textarea`  | 左栏输入框（占满高度、等宽字体） |
| `.result-area`      | 右栏结果容器（可滚动）           |

| `.error-text`       | 错误信息（危险色）               |
| `.truncate-hint`    | 截断提示                         |
| `.code-output`      | 代码输出（pre 等宽、自动换行）   |

#### Flex 布局约定

- 满高容器：`height:100%` + `display:flex` + `flex-direction:column`。
- 可滚动子区：加 `min-height:0`（或 `min-width:0`），配合 `overflow:auto/hidden`。
- 间距优先用 `--app-space-*`、`--app-gap-*` 变量，不用魔法数字。
- 固定元素加 `flex-shrink:0`，防止被压缩。

### 5.6 API / IPC 规范

#### 调用方式

渲染进程统一通过 `window.electronAPI` 调用（类型声明见 `src/types/ipc.ts`）：

```ts
// 调用主进程（返回 Promise）
const result = await window.electronAPI.invoke('channel:action', ...args)

// 监听主进程事件（返回清理函数，组件卸载时调用）
const cleanup = window.electronAPI.on('event:xxx', (data) => { ... })
onUnmounted(cleanup)
```

#### Channel 命名规范

采用 `<域>:<动作>` 格式，动作使用 camelCase：

- `settings:get` / `settings:set` / `settings:getSchema`
- `notification:create` / `notification:markRead` / `notification:markAllRead` / `notification:clearAll` / `notification:getAll` / `notification:getUnreadCount`
- `store:get` / `store:set` / `store:delete` / `store:keys`
- `system:getVersion` / `system:selectFile` / `system:saveFile` / `system:selectDirectory`
- `tool:execute` / `tool:saveFile`
- `sys:showNotification`
- `event:*`（主进程到渲染进程推送）：`event:themeChanged`、`event:notificationCreated`、`event:notificationsCleared`、`event:output`
- `menu:event`（菜单事件）

#### 新增 IPC 通道流程（强制）

1. 在 `electron/main.ts` 的 `registerIpc()` 中注册 `ipcMain.handle('xxx:yyy', ...)`。
2. 在 `electron/preload.ts` 的 `ALLOWED_PREFIXES` 中登记对应前缀，否则调用会被拒绝。
3. 渲染进程通过 `window.electronAPI.invoke('xxx:yyy', ...)` 调用。

#### 工具执行器规范（ToolExecutor）

需要主进程能力的工具，必须通过执行器接入，**不得**为单个工具新增专用 IPC 通道：

```ts
// electron/services/<category>/index.ts
import { toolExecutors, type ToolExecuteResult } from '@electron/services/tool-executor.service'

toolExecutors.register({
  id: 'excel-mask', // 与 Tool.executors 中的 id 一致
  async execute(params, ctx): Promise<ToolExecuteResult> {
    // 校验参数 -> 处理 -> 返回结果
    return { success: true, data: {/* ... */} }
    // 或 return { success: false, error: '原因' }
  },
})
```

**返回结构约定**：

```ts
interface ToolExecuteResult {
  success: boolean
  data?: Record<string, unknown>
  error?: string
}
```

- 失败时 `success:false` 并给出可读的中文 `error`，`error` 会直接展示给用户。
- 主进程通过 `tool:execute` 统一分发，未找到执行器返回 `{ success:false, error:'未找到执行器: xxx' }`。

#### 参数与二进制数据传输

- 文本参数直接传字符串。
- 二进制数据（如 Excel 文件）在渲染进程转成 `Uint8Array` 传入；保存文件时通过 `tool:saveFile` 传 `number[]`（字节数组）。

```ts
// 读取文件为字节
const buffer = await file.arrayBuffer()
const bytes = new Uint8Array(buffer)
const result = await window.electronAPI.invoke('tool:execute', 'excel-mask', { bytes, skipRows })

// 保存二进制
const bytes = base64ToBytes(base64)
await window.electronAPI.invoke('tool:saveFile', savePath, Array.from(bytes))
```

#### 文件读写与保存

- 打开文件：渲染进程用 `<el-upload :auto-upload="false">` 读文件，或 `system:selectFile` 选择路径。
- 保存文件：先 `system:saveFile` 弹出保存对话框拿到路径，再 `tool:saveFile` 写入字节。
- 禁止渲染进程直接操作文件系统（Node 能力已关闭）。

#### 性能规范

- 大文本渲染前用 `truncateLines()`（`src/utils/text.ts`）限制显示行数（默认 200 行），完整文本保留用于复制/保存。
- 输入防抖：对输入框的实时转换使用 300ms debounce，避免高频调用主进程。
- 批量数据预览限制在主进程执行器中（如 Excel 预览 `PREVIEW_MAX_ROWS = 200`）。

---

### 5.7 状态管理规范

- 跨组件共享状态使用 **Pinia**，文件命名 `*.store.ts`。
- Store 采用 setup 风格（`defineStore('id', () => { ... })`），state 用 `ref`，派生值用 `computed`，操作暴露为函数。
- 局部状态优先使用组件内 `ref` / `reactive`，**不要**把所有状态都放进全局 Store。
- 需要跨组件复用的组合逻辑抽到 `src/composables/`，命名 `useXxx.ts`。
- 持久化：面板折叠等 UI 偏好用 `localStorage`；业务配置用 `settings:set`（主进程持久化）。

---

### 5.8 日志与通知规范

#### 日志（logStore）

- 统一通过 `useLogStore()` 的 `addLog(type, message)` 记录日志，类型为 `info | success | warning | error`。
- 用户可感知的操作结果（成功/失败/保存/复制）都应记录一条日志。
- 全局错误已自动接入日志面板（Vue errorHandler、`window.onerror`、`unhandledrejection`、`console.error/warn` 劫持），组件内**不要**重复包裹全局错误。

```ts
const logStore = useLogStore()
logStore.addLog('success', '脱敏文件已保存')
logStore.addLog('error', '保存失败: ' + (e.message || '未知错误'))
```

#### 系统通知

- 需要弹出 Windows 原生通知时，调用 `maybeShowSysNotification(title, body)`（`src/utils/sysNotification.ts`），它会按设置（总开关/静默/显示时长）自动判断。

---

### 5.9 设置规范

- 新增应用设置项时，在 `assets/settings_schema.json` 中添加定义，字段：`key`（点号嵌套）、`label`、`type`、`default`、`options`（combo 用）、`min/max/step`（spinbox 用）、`description`、`depends_on`/`depends_value`（条件显隐）。
- 设置 key 使用点号分层，如 `notification.enabled`、`appearance.logPanelHeight`。
- 主进程 `AppSettings` 会自动按 Schema 生成默认值并持久化。
- 设置写入统一走 `settings:set`，读取走 `settings:get`。

---

### 5.10 错误处理规范

- 主进程执行器内部捕获异常，统一返回 `{ success:false, error: message }`，**不向上抛异常**。
- 渲染进程调用 IPC 用 `try/catch` 包裹，失败时给用户可见的提示（`parseError` / `logStore.addLog('error', ...)`）。
- 主进程已注册 `uncaughtException` / `unhandledRejection` 全局捕获并回推渲染进程，开发时注意排查日志面板。
- 非关键操作（如系统通知）失败应静默降级，不影响主流程。

## 6. 新增工具指南

### 6.1 纯前端工具（无主进程依赖）

1. 创建 `src/tools/<category>/<ToolName>.vue` 组件（PascalCase），复用 `ToolLayout`。
2. 创建 `src/tools/<category>/index.ts`，导出 `ToolCategory` 对象：

```ts
import type { ToolCategory } from '@/types/tool'
import MyTool from '@/tools/<category>/MyTool.vue'

export const myCategory: ToolCategory = {
  id: '<category>',
  label: '类别名称',
  icon: 'Grid', // Element Plus 图标名
  tools: [
    {
      id: 'my-tool',
      label: '工具名称',
      description: '功能简述',
      icon: 'Files',
      component: MyTool,
      // 无主进程能力时省略 executors
    },
  ],
}
```

3. 在 `src/tools/index.ts` 的 `registerBuiltinTools()` 中注册：

```ts
import { myCategory } from '@/tools/<category>'
export function registerBuiltinTools(): void {
  // ...
  toolRegistry.register(myCategory)
}
```

完成。侧边栏菜单、首页卡片、路由会自动生成，无需其他改动。

### 6.2 需要主进程能力的工具

1. 按 6.1 步骤注册工具，并在 `Tool` 上声明 `executors: ['my-executor']`。
2. 创建 `electron/services/<category>/index.ts`，注册执行器：

```ts
import { toolExecutors, type ToolExecuteResult } from '@electron/services/tool-executor.service'

toolExecutors.register({
  id: 'my-executor', // 与 Tool.executors 一致
  async execute(params, ctx): Promise<ToolExecuteResult> {
    // 校验 params -> 处理 -> 返回 { success, data } / { success:false, error }
  },
})
```

3. 在 `electron/main.ts` 顶部 import 该模块（触发注册副作用）：

```ts
import '@electron/services/<category>'
```

4. 在组件中调用：

```ts
const result = await window.electronAPI.invoke('tool:execute', 'my-executor', {/* params */})
if (result.success) {
  /* 使用 result.data */
} else {
  parseError.value = result.error
}
```
